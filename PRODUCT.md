# Product

## Register

brand

## Users

Product engineers, QA leads, and technical leads at small React Native and Expo agencies. They ship mobile applications for clients, work primarily through GitHub and continuous integration, and need to show that a change was tested without asking a client or reviewer to interpret raw automation logs.

## Product Purpose

Zeno Mobile Runner turns mobile interactions into deterministic scenarios and traceable product evidence. The public website should make that value understandable within seconds, show real proof from the product, and convert qualified visitors into paid Zeno Proof Cloud design partners.

Success means a visitor can quickly answer three questions: what Zeno proves, how it fits their existing workflow, and how to start a paid pilot or install the runner.

## Brand Personality

Minimal, fun, and straight to the point. Zeno should feel technically rigorous without becoming severe, and playful without becoming childish. The voice is confident, candid, concise, and comfortable showing how the product works.

PostHog is a positive reference for authored personality, functional humour, visible product substance, and commitment to a coherent metaphor. Zeno must translate those principles into its own mobile release evidence identity rather than copying PostHog's visual system.

## Anti-references

The website must not resemble a generic AI-generated SaaS landing page. Avoid neon developer-tool clichés, gradient headlines, decorative glass panels, repetitive icon-card grids, fake terminal theatre, inflated claims, padded copy, and anonymous stock illustrations.

Do not copy PostHog's desktop metaphor, hedgehog character, warm orange palette, typography, or page composition.

## Design Principles

1. **Show proof before making promises.** Real trace timelines, mobile screenshots, redaction states, and pull-request evidence should carry the story.
2. **Make technical depth approachable.** Explain the workflow in plain language while keeping real artifacts available for scrutiny.
3. **Use one coherent metaphor.** Treat Zeno as a mobile release flight recorder: it captures what happened, makes failure legible, and provides evidence for approval.
4. **Make play functional.** Humour and interaction should clarify the product, reward attention, or make evidence easier to explore.
5. **Keep every section purposeful.** Copy is brief, calls to action are explicit, and visual flourishes never compete with the proof.

## Accessibility & Inclusion

Meet WCAG 2.2 AA. All interactions must work with a keyboard, focus states must remain clearly visible, and meaning must not depend on color alone. Respect reduced-motion preferences and preserve comprehension when animation is disabled. Maintain readable type, strong contrast, descriptive alternative text, and responsive layouts that work from narrow mobile screens to large desktop displays.
